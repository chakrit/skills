# Plan the study

## 1. Bound the study

For a new study, finish **Initiate study** first. Keep its visual unknowns open for
options; do not ask them again as planning questions.

Read the request, existing application, authoritative requirements, and earlier
rulings. Name what the study must settle and what carries over unchanged: assets,
content, brand constraints, behavior. Treat other choices as open inside the preview;
do not erase the existing application's styles or files to obtain a blank slate.

Record scope, retained constraints, and authorization in the ledger. Ask only about
missing basics that prevent meaningful options; use alternatives or placeholders for
the rest. Keep nonvisual work outside initial builds without the user's justification.

Evidence: a bounded study goal and explicit carry-over list.

## 2. Distill decisions

Write one plan item per independent decision. Order by dependency: foundations, then
components, then compositions or end-to-end flows. Use sorting phase names such as
`Phase 1 · Foundations`. A later preview incorporates earlier rulings.

For each item record slug, decision, phase, dependencies, current status, preview
route, latest ledger event, and production handoff. Put real-build work and unrelated
questions in a separate backlog; do not make them preview questions.

Evidence: every in-scope decision has one item with its dependency edges.

## 3. Open the runnable work

With no frame, run **Build frame** first. With an existing frame, verify its contract
before reusing it. Run **Run a task** for every item whose dependencies are satisfied;
build independent previews in parallel with disjoint file ownership.

Give dependent items a visible queued status in the plan. Put unfinished previews in
the index's “Building” section, including work awaiting verification. Keep the top lists
for verified previews awaiting feedback. Do not present empty stubs as ready; labeled
missing-fact placeholders may accompany reviewable options.

Evidence: the plan accounts for active, queued, and blocked items; every active item
has an index entry and assigned owner.
