# Build options

## 1. Read the brief

Read the request, earlier rulings, active references, and allowed paths. Work only in
the assigned worktree. Shared layouts, stylesheets, dependencies, and configuration
remain read-only unless the brief assigns them. Do not start a server or run a full
build. Return missing shared capabilities to the coordinator.

Evidence: one decision, its constraints, and preview-owned paths identified.

## 2. Render comparable options

Use the construction and sizing contract in [frame.md](frame.md), section 2. Supply
option components and descriptors; do not rebuild or override the frame chrome.

Apply the brief's clear mandates directly to the prototype. Explore its open visual
and interaction choices as distinct options within the requested constraints. Do not
replace an option set with one preferred implementation or add alternatives to a fully
specified mandate. Do not ask the coordinator or user to settle open choices before
building. Mock nonblocking missing facts and return only actual blockers that make
meaningful alternatives impossible.

Keep the route thin: metadata plus composition. Reuse one shared mock for every
option; vary only the decision being judged. Use one component per distinct idea or
one parameterized component for differences in values.

Apply settled rulings in context. Show page mocks in visit order. Use neutral content
such as “Customer quote goes here”; never invent claims, testimonials, or final copy.
Use supplied copy faithfully. For multilingual work, show a whole page per language.

For non-web work, use an Astro adapter component to show the artifact. Use SVG or an
image for diagrams; show documents or recordings with native browser elements and
retain the source file beside the preview. Supply a readable fallback and source link
when an embed needs an unavailable viewer. Do not rewrite the artifact as a web app.

For architecture diagrams, vary the boundary or topology being decided. Keep labels,
legend, scope, and assumptions consistent. Show relevant data flow and ownership;
put trade-offs the diagram cannot show in the toolbar's Notes panel. Compare at the same
scale and retain editable diagram sources, not just screenshots.

Make interactions detailed enough to judge. Use scripts when the preview needs them
and expose failures. Pause expensive scenes offscreen. Keep links inside existing study
routes or option anchors; render unavailable destinations as inert text. Do not connect
mock interactions to production mutations.

Allocate unused letters after the highest ever used: A–Z, then AA, AB, and so on.
Never recycle a retired letter. Keep referenced picks unchanged. Show only the active
round and its references; preserve earlier rounds through commits and ledger events.

Keep used knobs with meaningful ranges. Place names in the Options dropdown; put intent,
controls, readouts, and questions in the toolbar. The content pane shows only the
rendered option. Put each nonvisual question under a stable ID supplied by the coordinator.

Keep preview text short and plain: one idea per item, one or two sentences. Describe
intent, constraints, or caveats the render cannot show. Omit jargon, build narration,
and descriptions of what is already visible.

When new art is requested, compare inexpensive drafts within the approved budget and
keep the source image visible as an unchanged reference option. Crops, flips, or
rescaling do not count as new styles. Archive the drafts and pick before finalizing
the chosen option within the authorized scope and budget. Without generation
permission, show clearly labeled mocks and report the constraint.

Evidence: comparable options in context, option inventory, unchanged references,
knob defaults, and stable question IDs.

## 3. Return reviewable work

Keep every save importable: create replacement files before switching imports.
Run the assigned lightweight checks on owned paths; fix failures. Leave
`building: true`. Commit locally when allowed and report in three lines at most:
options and intent; checks and spend; branch, commits, and retained artifact paths.

Do not claim browser verification that the coordinator has not performed.

Evidence: check results, recoverable changes, actual spend, and an integration target.
