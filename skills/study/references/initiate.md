# Initiate the study

## 1. Extract the brief

Read the user's paragraph and the project's existing requirements. Record the intended
build, who uses it, known features, constraints, retained assets, and decisions to
explore. Separate the user's facts from agent assumptions. Reuse earlier answers.

Use the user's explicit study title. If none was given, infer a concise title from
the brief without asking. Record it in the brief for the preview site's browser title.

For each proposed decision, name the visual artifact the user can judge: page, control,
flow, diagram, image, or other visible comparison. Architecture boundaries and data
flow can be studied as diagrams even when the product is not a website.

Evidence: a titled brief with known facts, assumptions, and proposed visual decisions.

## 2. Route the unknowns

- **An option can show the answer:** plan alternatives. Do not ask the user to choose
  layouts, styles, visible feature arrangements, or competing flows before seeing them.
- **A missing fact can be mocked:** record a labeled assumption or placeholder, put the
  real question on the relevant preview, and keep building.
- **No meaningful option can be built:** ask one precise question about the missing
  basic fact, scope, or permission in the study's Questions panel. Pause only work that
  depends on its answer. If no study page can be built or reached, report the blocker
  in chat.
- **No clear visual comparison exists:** keep the item outside initial builds. Include
  it only after the user states why it belongs in this study and what evidence they
  intend to judge. Do not manufacture a visual excuse or silently expand the study.

A study explores unknowns. Do not turn this phase into a requirements questionnaire or
require every feature to be settled. For example, compare two onboarding flows rather
than asking which flow to build; use a labeled pricing placeholder rather than blocking
a layout study on final prices.

Evidence: unknowns assigned to options, placeholders, actual blockers, or excluded work;
the user's words justify each included nonvisual exception.

## 3. Start the first exploration

Write the brief and unknowns into the study record. Run **Plan the study** for the
visual decisions that can start now. Carry assumptions and open questions into builder
briefs; do not replace them with invented final requirements.

When the original request defines a meaningful authorized study, proceed from it.
Ask for clarification only on the actual blockers above. A feature discovered later
enters the plan through the same visual-fit check.

Evidence: an actionable brief, initial visual decisions, and recorded blockers; open
exploration questions remain open for the first option set.
