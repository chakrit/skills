# Apply a ruling

## 1. Record and classify

Resolve the target preview. Append the user's exact words, date, round, and values to
the ledger before interpreting them. Pass new instructions to a running builder
immediately; update its brief and preserve newer changes during integration.

Separate mandated changes from open choices before routing the request. Apply mandates
to the prototype; build alternatives for meaningful unspecified details. Keep earlier
picks for independent decisions. A request for motion does not reopen settled placement.

| User says                           | Branch                                                            |
| ----------------------------------- | ----------------------------------------------------------------- |
| `make it animate, subtle and quick` | Compare motion options within those constraints; wait for a pick  |
| `use a 100 ms opacity fade only`    | Apply the specified motion directly to the prototype              |
| `go B`, `go B at 4%`                | Settle with the exact pick and values                             |
| `go B but smoother`                 | New round based on B; compare the unspecified refinement          |
| `more on E and F`                   | New options with E and F unchanged as references                  |
| `go I with J's headers`             | Render the specified blend; settle that choice after verification |
| `go back to G`                      | Resume G; retire later active rounds without rewriting history    |
| `<slug>-Q2: <answer>`               | Apply answer; retire Q2 without renumbering others                |
| `decide for me`                     | Choose, apply within scope, label as delegated                    |
| `A, once type is fixed`             | Hold open on the named dependency                                 |
| `re-open it`                        | Reopen and make a new round                                       |
| `separate X from Y`                 | Split into two decisions and preview tasks                        |

When the target cannot be resolved, record a blocker in the preview's Questions panel.
Continue work that does not depend on that answer.
When the target is clear and meaningful details remain open, build those readings in
the next round. Do not ask the user to specify them before seeing options or invent a
final pick from a refinement request.

Evidence: verbatim ruling and the condition selecting its branch.

## 2. Build or settle

For a new round, run **Run a task** with the ruling, retained references, next unused
letter, and updated round note. Remove rejected options from the active display;
retain their recoverable sources. Put the current ruling and date first in the
preview's notes. Reopening clears the current settled date, preserving ledger history.

After the comparison is verified, report it ready and wait for the user's selection.
This is a Wait. Readiness does not settle the decision.

For a clear mandate, run **Run a task** to apply and verify the specified change directly
in the prototype. Record that choice as a ruling. Keep any remaining open choices in
their comparison round; do not mark the whole preview settled while they remain open.
With no remaining open choice, use the final-pick settlement below for the mandated result.

For a final pick, run **Run a task** to keep only that pick, set `settled` to the
ruling date, and record the settled requirement in the project's authoritative spec
or the study plan. Mark the plan item settled after the coordinator verifies the
resulting preview.

Carry the exact chosen values into affected ongoing previews in the same pass. Update
running builders' briefs immediately; use **Run a task** for previews awaiting review.
Keep each affected preview under edit until its update is verified. Retain settled
previews as snapshots; reopen one only when the user requests it.

Evidence: verified active round or settled pick; updated ongoing previews, builder
briefs, plan, notes, and ledger.

## 3. Hand off the pick

Record the real-build targets, selected assets, exact values, and remaining work.
With existing implementation authorization, apply the pick to production within that
scope and record verification. Without it, mark the handoff pending; the study decision
remains settled.

Archive the settled preview as a snapshot. Retire it only when the user requests it
and repository cleanup rules permit that action. Keep the ledger and retained artifacts.
When the user asks to revise a settled pick, record a superseding ruling and reopen.
Undo applied work only within the authorized correction, without rewriting history.

Evidence: applied or pending handoff with target paths and recoverable decision history.
